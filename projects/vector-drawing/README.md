# Semantic Vector Drawing — v0.1

A deterministic vector-drawing prototype for clean fashion flats.

The AI-facing layer should describe **what exists**. This package owns **how the lines are drawn**.

```text
prompt / reference interpretation
        ↓
validated garment spec
        ↓
semantic drawing model
        ↓
front / back technical-flat view
        ↓
deterministic geometry
        ↓
geometry cleanliness validation
        ↓
SVG (authoritative illustration)
DXF (CAD-friendly artwork export)
```

## Why

Raster image generation is good at visual ideation but unreliable for technical line quality. It can create doubled contours, waviness, accidental asymmetry and inconsistent construction details. This prototype replaces pixel guessing with named curves, explicit symmetry and testable geometry rules.

## v0.1 scope

Supported garment semantics:

- garment: `dress`
- front neckline: `round | v`
- sleeve: `sleeveless | short`
- silhouette: `a_line | straight`
- length: `mini | knee | midi | maxi`
- back neckline: `same_as_front | shallow_round`
- back closure: `none | centre_zip`
- front darts: `none | waist_pair` (optional; omitted = unspecified)
- back darts: `none | waist_pair` (optional; omitted = unspecified)
- technical-flat view: `front | back`

Front-only generation does not require back fields. Back generation requires `back_neckline` and `back_closure`. Dart fields are deliberately optional so the model can distinguish **unknown/unspecified** from an explicit `none`.

The output contains stable semantic path IDs such as:

```text
outline.neckline
outline.shoulder.left
outline.armhole.left
outline.side.left
outline.hem
detail.dart.front.left
detail.dart.front.right
detail.dart.back.left
detail.dart.back.right
detail.back_closure.centre_zip
guide.centre_front
guide.centre_back
```

Left/right geometry is generated by exact mirroring where symmetry is intended.

## Front / back semantic boundary

The same `DressSpec` may drive both views, but the back view is not inferred from the front.

```text
DressSpec
├── neckline
├── sleeve
├── silhouette
├── length
├── back_neckline
├── back_closure
├── front_darts
└── back_darts
```

Supported back behavior:

```text
back_neckline = same_as_front
    -> reuse the explicitly requested front neckline geometry

back_neckline = shallow_round
    -> render a distinct shallow round back neckline

back_closure = none
    -> no closure line is drawn

back_closure = centre_zip
    -> render a semantic centre-back zipper line
```

If a caller requests a back view without `back_neckline` and `back_closure`, generation safe-stops. The engine does not invent a zipper, neckline or closure.

## Dart semantics and production boundary

Darts are now represented as explicit construction semantics:

```text
front_darts = waist_pair
    -> detail.dart.front.left/right

back_darts = waist_pair
    -> detail.dart.back.left/right

front_darts/back_darts = none
    -> explicitly confirmed no waist-dart pair

front_darts/back_darts = omitted / null
    -> unspecified; no dart geometry is rendered, but this is NOT treated as confirmed none
```

The current dart coordinates are **technical-flat illustration policy only**. They communicate that a dart construction feature exists. They are not production pattern values and must not be used as evidence for:

- dart intake;
- dart length;
- exact dart placement;
- waist suppression allocation;
- production sewing geometry.

This separation is intentional because the production garment engine still requires independently validated dart mathematics and patternmaking policy.

## Natural-language input

The prompt layer is deliberately strict. Every required semantic category must be stated explicitly, and conflicting or unsupported language safe-stops rather than being guessed.

Accepted front examples:

```text
round-neck short-sleeve midi A-line dress
round-neck short-sleeve midi A-line dress front waist darts
圓領 短袖 中長 A字 連衣裙 前腰省
```

Accepted back examples:

```text
round-neck short-sleeve midi A-line dress shallow round back neckline centre-back zipper back waist darts
圓領 短袖 中長 A字 連衣裙 淺圓後領 後中拉鏈 後腰省
```

Rejected examples include:

```text
a nice midi dress
round-neck V-neck short-sleeve midi A-line dress
round-neck long-sleeve midi A-line dress
round-neck short-sleeve midi A-line dress front waist darts no front darts
```

A request for `--view back` also rejects a prompt that omits `back_neckline` or `back_closure`.

This boundary is intentional: a future LLM/image-understanding layer may propose semantics, but only validated supported values may reach the geometry engine.

## Geometry cleanliness validation

`vector_drawing.validation.validate_drawing()` currently checks:

- zero-length / collapsed segments;
- duplicate geometry, including reversed duplicates;
- intra-path self-intersection;
- exact left/right mirror symmetry for paired semantic roles, including dart pairs;
- expected semantic endpoint joins between neckline, shoulder, armhole/sleeve, side and hem;
- tangent continuity at smooth round-neck cubic joins.

The validator returns structured issue codes such as:

```text
ZERO_LENGTH_SEGMENT
DUPLICATE_GEOMETRY
SELF_INTERSECTION
SYMMETRY_MISMATCH
ENDPOINT_DISCONTINUITY
CURVE_TANGENT_DISCONTINUITY
```

This makes line cleanliness an engineering property rather than a visual guess.

## Run

Front view with explicit front darts:

```bash
python -m vector_drawing.cli \
  --prompt "round-neck short-sleeve midi A-line dress front waist darts" \
  --view front \
  --validate \
  --svg out/dress-front.svg \
  --dxf out/dress-front.dxf
```

Back view with explicit semantics and back darts:

```bash
python -m vector_drawing.cli \
  --prompt "round-neck short-sleeve midi A-line dress shallow round back neckline centre-back zipper back waist darts" \
  --view back \
  --validate \
  --svg out/dress-back.svg \
  --dxf out/dress-back.dxf
```

JSON input may provide:

```json
{
  "garment": "dress",
  "neckline": "round",
  "sleeve": "short",
  "silhouette": "a_line",
  "length": "midi",
  "back_neckline": "shallow_round",
  "back_closure": "centre_zip",
  "front_darts": "waist_pair",
  "back_darts": "waist_pair"
}
```

Run tests:

```bash
python -m unittest discover -s tests -v
```

## Important DXF boundary

The v0.1 DXF exporter writes **standard DXF R12 artwork geometry** by deterministically sampling cubic curves into polylines.

It is **not** DXF-AAMA / DXF-ASTM and must not be confused with the repository's factory garment-pattern pipeline.

SVG is the authoritative illustration output in v0.1.
